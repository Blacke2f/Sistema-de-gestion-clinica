Las tablas PACIENTES, CONSULTAS, NOMINA e INVENTARIO ahora tienen columna deleted_at para borrado logico (Soft Delete). Los registros eliminados se conservan en la BD con deleted_at != NULL.
La tabla USUARIOS ahora soporta 7 roles: admin, medico, recepcionista, enfermera, farmaceutico, contador, laboratorista.
Sistema institucional: Los medicamentos se reciben por asignacion/donacion. No existen tablas de precios ni facturacion en esta instalacion.

Relaciones entre Entidades

Cardinalidad y comportamiento ON DELETE de cada relación

  • PACIENTES → CONSULTAS 1 a N Un paciente puede tener muchas consultas. ON DELETE CASCADE.
  • USUARIOS → CONSULTAS 1 a N Un usuario médico puede atender muchas consultas. ON DELETE SET NULL.
  • NOMINA → CONSULTAS 1 a N Un empleado médico puede atender muchas consultas.
  • CONSULTAS → CONSULTAS_MEDICAMENTOS 1 a N Una consulta puede incluir varios medicamentos. ON DELETE CASCADE.
  • INVENTARIO → CONSULTAS_MEDICAMENTOS 1 a N Un medicamento puede estar en varias consultas.
  • INVENTARIO → INVENTARIO_MOVIMIENTOS 1 a N Un medicamento tiene muchos movimientos. ON DELETE CASCADE.
  • CONSULTAS → INVENTARIO_MOVIMIENTOS 1 a N Una consulta puede generar salidas de inventario. ON DELETE SET NULL.
  • USUARIOS → INVENTARIO_MOVIMIENTOS 1 a N Un usuario registra los movimientos.
  • USUARIOS → MENSAJES 1 a N Un usuario puede enviar y recibir muchos mensajes. ON DELETE CASCADE.
  • USUARIOS → BITACORA 1 a N Cada acción del usuario queda registrada. ON DELETE CASCADE.
  • USUARIOS → NOTIFICACIONES 1 a N Un usuario puede recibir muchas notificaciones. ON DELETE CASCADE.
  • USUARIOS → SOLICITUDES_INVENTARIO 1 a N Un usuario puede crear muchas solicitudes. ON DELETE CASCADE.
  • INVENTARIO → SOLICITUDES_INVENTARIO 1 a N Un medicamento puede tener muchas solicitudes.
  • SOLICITUDES_INVENTARIO → SOLICITUD_ITEMS 1 a N Una solicitud contiene uno o varios items. ON DELETE CASCADE.
  • USUARIOS → PERMISOS_USUARIO 1 a N Un usuario puede tener permisos configurados para múltiples módulos. ON DELETE CASCADE.
  • INVENTARIO → SOLICITUD_ITEMS 1 a N Un medicamento puede aparecer en varios items de solicitud.
  • PACIENTES → CITAS 1 a N Un paciente puede tener muchas citas. ON DELETE CASCADE.
  • USUARIOS → CITAS 1 a N Un medico puede tener muchas citas asignadas. ON DELETE SET NULL.
  • CONSULTAS → CITAS 1 a 1 Una cita puede convertirse en una consulta. ON DELETE SET NULL.
  • CONSULTAS → SIGNOS_VITALES 1 a 1 Cada consulta tiene un registro de signos vitales. ON DELETE CASCADE.
