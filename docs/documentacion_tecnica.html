Descripción General

Sistema de Gestión Clínica — qué es y qué hace SISGECLIN

SISGECLIN v3.0 es una aplicación web integral diseñada en Laravel para administrar todos los procesos operativos de una clínica médica desde una sola plataforma centralizada. Pensada para clínicas institucionales que reciben medicamentos por asignación (sin módulo de facturación ni precios).

Arquitectura del Sistema

Patrón MVC con capas de Servicios, Middlewares y Enums

Router (web.php)

Resuelve cada URL, aplica la cadena de middlewares y despacha al controlador correcto.

Middleware Pipeline

auth, role y permiso actúan como filtros secuenciales antes de llegar al controlador.

Controller

23 controladores, uno por módulo. Valida la petición, coordina modelos y servicios.

Service Layer

InventarioService, RecetaService y GoogleDriveSyncService encapsulan lógica con transacciones DB.

Eloquent ORM

20 modelos con relaciones, scopes, accessors, casts y soft deletes. Una tabla = un modelo.

Blade Views

Plantillas compiladas con layout principal. Sin frameworks JS pesados en el frontend.

Flujo completo de una petición

1

Cliente (Navegador)

El usuario hace clic en "Guardar". El formulario envía un POST /pacientes con el token CSRF incluido.

2

Apache + .htaccess

mod_rewrite redirige todas las peticiones a public/index.php (front controller de Laravel).

3

Bootstrap de Laravel

bootstrap/app.php carga la aplicación y registra los middlewares role y permiso como alias.

4

Pipeline de Middlewares

Se ejecutan en orden: EncryptCookies → StartSession → VerifyCsrfToken → auth → permiso:pacientes,crear.

5

PacientesController@store

Valida los campos con $request->validate(). Fallos → redirige de vuelta con errores al formulario.

6

Eloquent ORM

Paciente::create($data) inserta en la BD con escape automático de datos (previene SQL injection).

7

Bitácora

Bitacora::registrar() graba la acción con IP y timestamp. Registro inmutable de auditoría.

8

Respuesta

El controlador redirige con redirect()->back()->with('success', '...'). El usuario ve el mensaje de éxito.

Cada módulo tiene su propio Controlador, su conjunto de rutas en web.php y sus permisos configurables. Los administradores tienen acceso total a todos los módulos automáticamente.

Seguridad

Capas de protección implementadas en el sistema

Contraseñas con Bcrypt

Todas se almacenan con bcrypt. Nunca en texto plano. Laravel verifica con Hash::check() automáticamente.

Rate Limiting en Login

Máximo 5 intentos por usuario y por IP en 60 segundos. El sistema bloquea automáticamente al superar el límite.

Protección CSRF

Token CSRF obligatorio en todos los formularios POST/PUT/DELETE. Se regenera en cada logout.

Regeneración de Sesión

session()->regenerate() al hacer login previene ataques de session fixation.

Middlewares de Acceso

auth bloquea anónimos. role verifica rol. permiso verifica permisos granulares por módulo.

Datos Protegidos en JSON

password y remember_token están en $hidden del modelo — nunca aparecen en respuestas JSON.

Soft Delete en tablas críticas

Los registros nunca se borran físicamente. Se marcan con deleted_at para preservar el historial médico.

Throttle en Rutas Sensibles

Crear paciente: 30/min. Eliminar: 20/min. Editar: 60/min. Protege contra automatización masiva.

Contraseña Segura en Registro

Mín. 8 caracteres, mayúsculas, minúsculas, números, símbolos y verificación contra HaveIBeenPwned.

php artisan migrate php artisan db:seed
6

php artisan storage:link

Abrir el navegador en http://sisgeclin.test e iniciar sesión con las credenciales del paso anterior.

Acceso desde otra PC en la misma red

La PC servidor debe tener su red configurada como Privada en Windows para permitir conexiones desde otros dispositivos.
1

Obtener IP del servidor

Ejecutar ipconfig en la terminal de la PC servidor y anotar la "Dirección IPv4" (ej: 10.1.1.114).

2

Editar el archivo hosts en la OTRA PC

Abrir el Bloc de notas como Administrador y editar: C:\Windows\System32\drivers\etc\hosts

10.1.1.114 sisgeclin.test
3

Acceder

En la otra PC abrir el navegador y escribir http://sisgeclin.test. El sistema cargará normalmente.

Comandos y procedimientos para el mantenimiento preventivo

Limpiar caché del sistema

php artisan cache:clear # Limpia caché de datos php artisan config:clear # Limpia caché de configuración php artisan view:clear # Limpia vistas Blade compiladas php artisan route:clear # Limpia caché de rutas

Optimizar para producción

php artisan config:cache # Cachear configuración — mejora el arranque php artisan route:cache # Cachear rutas — mejora el rendimiento php artisan view:cache # Pre-compilar vistas Blade

Revisar errores del sistema

Laravel registra todos los errores en storage/logs/laravel.log. Los errores más recientes aparecen al final. Busca las líneas con [stacktrace] para ver el origen exacto del problema.

Limpiar archivos temporales de Composer

# Libera espacio eliminando archivos ZIP atascados del /q "vendor\composer\tmp-*.zip" del /q "vendor\composer\tmp-*.zip~"

Respaldo de base de datos

php artisan backup:run # Respaldo completo (DB + archivos) php artisan backup:run --only-db # Solo base de datos

Ejecutar pruebas automatizadas

php artisan test
