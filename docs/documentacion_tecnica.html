Arquitectura del Sistema

Patron MVC con deteccion dinamica de URL

Punto de entrada

SISGECLIN/index.php detecta el host actual y redirige a public/ automaticamente.

mod_rewrite

public/.htaccess redirige todas las peticiones a public/index.php (front controller).

URL Dinamica

AppServiceProvider llama a URL::forceRootUrl() con el host real. Funciona desde localhost y desde cualquier IP de red.

Middleware

auth protege todas las rutas autenticadas. role:admin restringe modulos administrativos.

Vistas Blade

Layout principal layouts/app.blade.php con sidebar, navbar, notificaciones y modo oscuro.

Sesiones

Driver file almacenado en storage/framework/sessions/. Cookie sin dominio fijo para compatibilidad multi-IP.

Flujo de una peticion

1

Cliente

El navegador hace una peticion HTTP a http://IP/SISGECLIN/public/ruta

2

Apache + .htaccess

mod_rewrite redirige todo a public/index.php

3

Bootstrap

Laravel carga bootstrap/app.php, registra middleware y service providers

4

Router

routes/web.php resuelve la ruta y aplica middleware (auth, role)

5

Controller

El controlador ejecuta la logica, consulta modelos Eloquent y retorna una vista o JSON

6

Vista Blade

La plantilla se compila y se envia al cliente como HTML

Instalacion y Configuracion

Pasos para poner en marcha el sistema

1

Copiar el proyecto

Coloca la carpeta SISGECLIN en E:\Xampp\htdocs\

2

Instalar dependencias

Abre CMD en la carpeta del proyecto y ejecuta: composer install

3

Configurar .env

Copia .env.example a .env y edita los datos de base de datos.

4

Crear la base de datos

En phpMyAdmin crea la BD: CREATE DATABASE sisgeclin_laravel CHARACTER SET utf8mb4;

5

Importar el SQL

Importa database/sisgeclin_laravel.sql en phpMyAdmin. Incluye estructura y datos iniciales.

6

Limpiar cache

Ejecuta: php artisan config:clear && php artisan view:clear

7

Acceder

Abre el navegador en http://localhost/SISGECLIN/public

Configuracion .env clave

APP_NAME=SISGECLIN
APP_DEBUG=false
APP_URL=http://localhost/SISGECLIN/public

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=sisgeclin_laravel
DB_USERNAME=root
DB_PASSWORD=

SESSION_DRIVER=file
SESSION_DOMAIN=
SESSION_SECURE_COOKIE=false
APP_URL solo es un fallback. El sistema detecta el host real automaticamente, por lo que funciona desde localhost y desde cualquier IP de red sin cambiar este valor.

Seguridad

Mecanismos de proteccion implementados

Bcrypt (12 rounds)

Todas las contrasenas se almacenan hasheadas. Nunca en texto plano.

CSRF Token

Todos los formularios incluyen token CSRF de Laravel. Las peticiones AJAX lo envian en el header.

Session Fixation

La sesion se regenera tras cada login exitoso para prevenir ataques de fijacion de sesion.

Cuentas Desactivadas

Los usuarios con activo=false no pueden iniciar sesion aunque tengan credenciales validas.

Control por Rol

Middleware CheckRole.php verifica el rol antes de cada accion administrativa.

Acceso en Red Local

Como acceder desde otros dispositivos en la misma red

1

Ejecutar ABRIR_FIREWALL.bat

Clic derecho sobre el archivo en la raiz del proyecto y selecciona Ejecutar como administrador. Solo necesario una vez.

2

Verificar la IP del servidor

Abre CMD y ejecuta ipconfig. Busca la IPv4 de tu adaptador de red (ej: 192.168.1.3).

3

Acceder desde otro dispositivo

En el navegador del otro dispositivo escribe: http://192.168.1.3/SISGECLIN/public

El sistema detecta automaticamente el host de cada peticion gracias a URL::forceRootUrl() en AppServiceProvider. No es necesario cambiar el .env para acceso desde red.
Ambos dispositivos deben estar conectados a la misma red WiFi o LAN. El servidor XAMPP debe estar corriendo.

Modulo de Solicitudes

Flujo de reposicion de inventario con trazabilidad completa

Tablas involucradas

TablaDescripcion
solicitudes_inventarioCabecera de la solicitud: numero_orden, estado, solicitado_por, atendida_por, numero_factura, atendida_at
solicitud_itemsItems de la solicitud: medicamento_id, cantidad, proveedor_sugerido, telefono_proveedor

Numero de orden

Formato: SOL-AAAAMM-XXXX donde AAAAMM es el año y mes actual y XXXX es un correlativo de 4 digitos. Ejemplo: SOL-202605-0001. Se genera automaticamente al crear la solicitud.

Flujo de aprobacion

1

Recepcionista/Medico crea solicitud

POST /solicitudes con array de items. Estado inicial: pendiente. Notificacion automatica a admins.

2

Admin aprueba

PATCH /solicitudes/{id}/atender con estado=aprobada. El frontend hace una segunda llamada a POST /inventario/entrada automaticamente.

3

Entrada registrada

El motivo de la entrada incluye el numero de orden y el numero de factura para trazabilidad completa.

Bitacora de Auditoria

Registro inmutable de todas las acciones criticas del sistema

La tabla bitacora se escribe automaticamente desde los controladores usando el metodo estatico Bitacora::registrar(). Las llamadas estan envueltas en try/catch para que un fallo en la bitacora nunca interrumpa la operacion principal.

CampoDescripcion
usuario_idID del usuario que realizo la accion
accionEtiqueta de la accion (CREAR USUARIO, ENTRADA INVENTARIO, etc.)
tablaTabla afectada (usuarios, nomina, inventario_movimientos, etc.)
registro_idID del registro afectado
detallesDescripcion legible de la accion realizada
ipDireccion IP del cliente
La vista de bitacora solo es accesible para administradores (middleware role:admin). Incluye paginacion con selector 10/15/20/50 registros y filtros por accion, usuario y rango de fechas.

Sistema de Permisos (ACL)

Control granular de acceso por usuario y modulo

El sistema de permisos permite al administrador definir exactamente qué puede hacer cada usuario en cada módulo. Se implementa con dos componentes principales:

Tabla permisos_usuario

Almacena un registro por usuario+módulo con 4 campos booleanos: puede_ver, puede_crear, puede_editar, puede_eliminar.

Middleware CheckPermiso

Se aplica a cada ruta con ->middleware('permiso:modulo,accion'). Verifica el permiso antes de ejecutar el controlador.

Método puedeEn()

Método del modelo Usuario que verifica un permiso. Los admins siempre retornan true sin consultar la BD.

Sidebar dinámico

El menú lateral carga los permisos del usuario una vez y oculta los módulos a los que no tiene acceso de ver.

Módulos protegidos

MóduloClaveAcciones protegidas

Consultasconsultasver, crear, editar, eliminar
Medicamentosmedicinaver, crear, editar, eliminar
Movimientosinventariover, crear (entradas/salidas)
Mensajesmensajesver, crear, eliminar
