Arquitectura del Sistema

Patron MVC con deteccion dinamica de URL

Punto de entrada

SISGECLIN/index.php detecta el host actual y redirige a public/ automaticamente.

mod_rewrite

public/.htaccess redirige todas las peticiones a public/index.php (front controller).

URL Dinamica

AppServiceProvider llama a URL::forceRootUrl() con el host real. Funciona desde localhost y desde cualquier IP de red.

Middleware

auth protege todas las rutas autenticadas. role:admin restringe modulos administrativos.

Vistas Blade

Layout principal layouts/app.blade.php con sidebar, navbar, notificaciones y modo oscuro.

Sesiones

Driver file almacenado en storage/framework/sessions/. Cookie sin dominio fijo para compatibilidad multi-IP.

Flujo de una peticion

1

Cliente

El navegador hace una peticion HTTP a http://IP/SISGECLIN/public/ruta

2

Apache + .htaccess

mod_rewrite redirige todo a public/index.php

3

Bootstrap

Laravel carga bootstrap/app.php, registra middleware y service providers

4

Router

routes/web.php resuelve la ruta y aplica middleware (auth, role)

5

Controller

El controlador ejecuta la logica, consulta modelos Eloquent y retorna una vista o JSON

6

Vista Blade

La plantilla se compila y se envia al cliente como HTML

Instalacion y Configuracion

Pasos para poner en marcha el sistema

1

Copiar el proyecto

Coloca la carpeta SISGECLIN en C:\laragon\www\ (Laragon) o C:\xampp\htdocs\ (XAMPP)

2

Instalar dependencias

Abre CMD en la carpeta del proyecto y ejecuta: composer install

3

Configurar .env

Copia .env.example a .env y edita los datos de base de datos.

4

Crear la base de datos

En phpMyAdmin crea la BD: CREATE DATABASE sisgeclin_laravel CHARACTER SET utf8mb4;

5

Importar el SQL

Importa database/sisgeclin_laravel.sql en phpMyAdmin. Incluye estructura y datos iniciales.

6

Limpiar cache

Ejecuta: php artisan config:clear && php artisan view:clear

7

Acceder

Abre el navegador en http://localhost/SISGECLIN/public

Configuracion .env clave

APP_NAME=SISGECLIN
APP_DEBUG=false
APP_URL=http://localhost/SISGECLIN/public

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=sisgeclin_laravel
DB_USERNAME=root
DB_PASSWORD=

SESSION_DRIVER=file
SESSION_DOMAIN=
SESSION_SECURE_COOKIE=false
APP_URL solo es un fallback. El sistema detecta el host real automaticamente, por lo que funciona desde localhost y desde cualquier IP de red sin cambiar este valor.

Modulos del Sistema

Descripcion funcional de cada modulo

Autenticacion

Login bcrypt, rate limiting (5 intentos/60s), registro con cuenta deshabilitada, regeneracion de sesion, bitacora automatica.

Dashboard

KPIs en tiempo real, grafica de consultas 7 dias (Chart.js), citas de hoy, consultas recientes, acciones rapidas, bitacora (admin).

Pacientes

CRUD con soft delete, busqueda, paginacion, exportacion CSV/PDF/Excel, notificacion automatica, acceso directo al expediente.

Expediente Clinico

Vista unificada del historial: timeline de consultas, signos vitales, recetas, top medicamentos frecuentes y estadisticas del paciente.

Agenda de Citas

Calendario FullCalendar (mes/semana/dia), 6 estados, conversion a consulta con un clic, notificacion al medico asignado.

Consultas

CRUD con soft delete, estados, signos vitales embebidos en el modal de edicion, exportacion por periodo.

Signos Vitales

Registro por consulta: presion, FC, FR, temperatura, SpO2, peso, talla, IMC (calculado automaticamente), glucosa. Historial por paciente.

Recetas Medicas

Generacion con numero correlativo (REC-AAAA-XXXX), multiples medicamentos, PDF A5 imprimible, soporte para recetas manuscritas escaneadas, vencimiento automatico via scheduler.

Medicamentos

CRUD con soft delete, alerta de stock bajo, exportacion PDF/Excel/CSV con indicador de estado. Sin precios — clinica institucional.

Movimientos

Entradas y salidas con historial, estadisticas por periodo, alerta automatica de stock bajo, datos de firma para auditoria.

Reportes Estadisticos

4 graficas Chart.js: consultas por mes, movimientos de inventario por tipo, top medicamentos mas despachados, distribucion por genero. KPIs filtrables por ano/mes.

Solicitudes

Solicitudes de reposicion multi-medicamento con numero de orden. Aprobacion registra entrada al inventario automaticamente.

Bitacora (admin)

Auditoria completa con filtros por accion, usuario y fecha. Paginacion configurable.

Permisos (admin)

ACL granular: ver/crear/editar/eliminar por modulo. 13 modulos configurables. Middleware CheckPermiso protege todas las rutas.

Mensajes

Mensajeria individual y masiva (admin), badge en tiempo real, notificacion al destinatario.

Nomina (admin)

CRUD con soft delete de empleados, cargos medicos aparecen en selector de consultas y citas, exportacion CSV/PDF/Excel.

Informes Medicos

Informes medico-ocupacionales Maxical: pre-empleo, prevacacional, postvacacional, egreso, reubicacion. PDF A5 con aptitud, diagnostico y estudios paraclinicos.

Gastos Medicos

Registro de gastos de atencion medica con conceptos itemizados e importes. Generacion de PDF A5 con tabla de conceptos y totales.

Examenes de Laboratorio

Solicitudes de examenes con checkboxes: hematologia, glicemia, urea, creatinina, colesterol, trigliceridos, orina, heces y otros. PDF A5 imprimible.

Usuarios (admin)

CRUD, activar/desactivar cuentas, gestion de permisos granulares, bitacora de todas las acciones.

Seguridad

Mecanismos de proteccion implementados

Bcrypt (12 rounds)

Todas las contrasenas se almacenan hasheadas. Nunca en texto plano.

CSRF Token

Todos los formularios incluyen token CSRF de Laravel. Las peticiones AJAX lo envian en el header X-CSRF-TOKEN.

Session Fixation

La sesion se regenera tras cada login exitoso para prevenir ataques de fijacion de sesion.

Rate Limiting (nuevo v3.0)

Maximo 5 intentos de login por IP/usuario en 60 segundos. Implementado con RateLimiter de Laravel.

Contrasenas Fuertes (nuevo v3.0)

Minimo 8 caracteres, al menos una mayuscula, una minuscula y un numero. Validacion con regex en registro.

Soft Deletes (nuevo v3.0)

Pacientes, consultas, empleados e inventario usan borrado logico. Los registros se conservan con deleted_at != null.

Cuentas Desactivadas

Los usuarios con activo=false no pueden iniciar sesion aunque tengan credenciales validas.

Control por Rol + ACL

Middleware CheckRole.php para acceso por rol. Middleware CheckPermiso.php para acceso granular por modulo y accion.

Bitacora de Auditoria

Todas las acciones criticas se registran con usuario, IP, fecha y detalles.

Backup Automatico (nuevo v3.0)

Comando db:backup genera dump SQL diariamente a las 2AM. Conserva los ultimos 7 dias en storage/app/backups/.

Acceso en Red Local

Como acceder desde otros dispositivos en la misma red

1

Ejecutar ABRIR_FIREWALL.bat

Clic derecho sobre el archivo en la raiz del proyecto y selecciona Ejecutar como administrador. Solo necesario una vez.

2

Verificar la IP del servidor

Abre CMD y ejecuta ipconfig. Busca la IPv4 de tu adaptador de red (ej: 192.168.1.3).

3

Acceder desde otro dispositivo

En el navegador del otro dispositivo escribe: http://192.168.1.3/SISGECLIN/public

El sistema detecta automaticamente el host de cada peticion gracias a URL::forceRootUrl() en AppServiceProvider. No es necesario cambiar el .env para acceso desde red.
Ambos dispositivos deben estar conectados a la misma red WiFi o LAN. El servidor Laragon (Apache) debe estar corriendo y con el firewall configurado.

Bitacora de Auditoria

Registro inmutable de todas las acciones criticas del sistema

La tabla bitacora se escribe automaticamente desde los controladores usando el metodo estatico Bitacora::registrar(). Las llamadas estan envueltas en try/catch para que un fallo en la bitacora nunca interrumpa la operacion principal.

CampoDescripcion
usuario_idID del usuario que realizo la accion
accionEtiqueta de la accion (CREAR USUARIO, ENTRADA INVENTARIO, etc.)
tablaTabla afectada (usuarios, nomina, inventario_movimientos, etc.)
registro_idID del registro afectado
detallesDescripcion legible de la accion realizada
ipDireccion IP del cliente
La vista de bitacora solo es accesible para administradores (middleware role:admin). Incluye paginacion con selector 10/15/20/50 registros y filtros por accion, usuario y rango de fechas.

  • Al crear: descuenta stock si medicamento_id existe en inventario
Cita
  • medico_nombre — desde empleado o usuario medico
  • estado_texto — 'en_curso' → 'En Curso'
  • estado_color — 'warning', 'success', etc.
  • fecha_hora_fin — fecha_hora + duracion_minutos
  • Scopes: hoy(), proximas(n), pendientes(), byDateRange()
Notificacion
  • Notificacion::notificarTodos(tipo, titulo, mensaje, icono, color, url)
  • Crea una notificacion para cada usuario activo del sistema
  • Usado por inventario, recetas, pacientes, citas, solicitudes
Bitacora
  • Bitacora::registrar(userId, accion, tabla, registroId, descripcion)
  • Llamado en cada operacion CRUD importante
  • Registra IP del cliente via request()->ip()
PermisosPorRol (clase)
  • PermisosPorRol::aplicar(userId, rol) — aplica los permisos por defecto del rol
  • Se llama automaticamente al crear o cambiar el rol de un usuario
  • Define 7 conjuntos de permisos: admin, medico, recepcionista, enfermera, farmaceutico, contador, laboratorista
Nota sobre consultas_medicamentos: La tabla pivote no tiene updated_at. La relacion en Consulta::medicamentos() usa ->withPivot([]) sin withTimestamps() para evitar errores al acceder a esa columna.

Scheduler (Tareas Programadas)

Automatizacion de tareas periodicas via Laravel Scheduler

Las tareas programadas se definen en routes/console.php y se ejecutan mediante el cron de Laravel. Para activarlas en produccion, agrega esta linea al crontab del servidor:

* * * * * cd /ruta/al/proyecto && php artisan schedule:run >> /dev/null 2>&1
TareaFrecuenciaDescripcion
inventario:check-stockDiario 06:00 AMEnvía un correo de alerta de stock crítico a farmacia@sisgeclin.com.
citas:actualizar-estadosCada horaMarca automáticamente como "no_asistio" las citas con retraso mayor a 2 horas.
backup:run --only-dbDiario 03:00 AMGenera archivo ZIP de la base de datos usando spatie/laravel-backup.
backup:cleanDiario 04:00 AMLimpia respaldos antiguos según la configuración de retención.
recetas:vencerDiario medianocheMarca como "vencida" todas las recetas activas cuya fecha_vencimiento ya paso.

Ejecutar backup manualmente (Spatie)

php artisan backup:run --only-db
php artisan backup:clean
Los backups se guardan en storage/app/SISGECLIN/ y se limpian automáticamente según la configuración en config/backup.php.

Logs del sistema

Los errores se registran en storage/logs/laravel.log. Para ver los ultimos errores en tiempo real usa:

php artisan pail
Mantener APP_DEBUG=false en produccion para no exponer trazas de error al usuario final. Los errores se registran en el log independientemente de este valor.
