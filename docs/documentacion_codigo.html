SISGECLIN v3.0 — Documentación técnica de clases, métodos, rutas y servicios del sistema

Esta referencia documenta la estructura interna del código de SISGECLIN v3.0, un sistema de gestión clínica construido con Laravel 13 y PHP 8.3+. El sistema implementa el patrón MVC con una capa de Servicios adicional para lógica de negocio crítica.

Las signaturas de método usan la notación: visibilidad función(Tipo $param): TipoRetorno — igual a PhpDoc/PSR-12.

AuthController

Autenticación, registro y control de sesiones

class AuthController app/Http/Controllers/AuthController.php
Gestiona el ciclo completo de autenticación. Aplica rate limiting de 5 intentos/min por IP+usuario en el método login().
pub login(Request $request): RedirectResponse
Valida credenciales con rate limiting. Verifica activo=true. Regenera sesión (session()->regenerate()) y registra en bitácora. Redirige al dashboard si es válido.
pub logout(Request $request): RedirectResponse
Registra logout en bitácora → Auth::logout() → $request->session()->invalidate() → regenerateToken() → redirige a /login.
pub register(Request $request): RedirectResponse
Crea usuario con activo=false. Valida contraseña segura (mín. 8 caracteres, mayúsculas, minúsculas, números, símbolos). Notifica a todos los administradores sobre la solicitud pendiente.
Rate limiting configurado en bootstrap/app.php como throttle:5,1 aplicado sobre la ruta POST /login.

PacientesController

CRUD completo de pacientes con búsqueda, paginación y exportación

class PacientesController app/Http/Controllers/PacientesController.php
Middleware en rutas individuales: permiso:pacientes,crear, permiso:pacientes,editar, etc. Usa throttle para proteger contra automatización masiva.
pub index(Request $request): View
Lista paginada con búsqueda por nombre, apellido o cedula. 15 registros por página. Requiere permiso pacientes.ver.
pub store(Request $request): RedirectResponse
Valida y crea un paciente. throttle: 30/min Registra en bitácora y notifica al equipo. Redirige con mensaje de éxito.
pub update(Request $request, Paciente $paciente): RedirectResponse
Actualiza datos con validación de cédula única (ignorando el paciente actual). throttle: 60/min
pub destroy(Paciente $paciente): RedirectResponse
Soft delete — marca deleted_at. throttle: 20/min El paciente queda en la BD para preservar el historial clínico.
pub exportarCsv(): StreamedResponse
Descarga CSV con todos los pacientes activos usando el trait ExportsToCSV.

RecetasController

Prescripción médica, generación de PDFs y dispensación al inventario

class RecetasController app/Http/Controllers/RecetasController.php
Usa RecetaService para la lógica de dispensación. La dispensación descuenta stock vía InventarioService con transacción atómica.
pub imprimir(Receta $receta): Response
Genera el PDF A5 de la receta con mPDF. Retorna la respuesta inline para visualizar en el navegador.
pub anular(Receta $receta): RedirectResponse
Cambia estado a anulada. Solo aplica si la receta está en estado activa.
pub dispensar(Request $request, Receta $receta): RedirectResponse
Llama a RecetaService::dispensar(). Este llama a InventarioService::registrarSalida() por cada ítem. Toda la operación es atómica (una transacción DB). Marca la receta como dispensada.
pub activas(Paciente $paciente): JsonResponse
Ruta AJAX: retorna JSON con las recetas activas del paciente para autocompletar en el formulario de salida de inventario.

InventarioService

Gestión transaccional y con locks pesimistas de las operaciones de stock

service InventarioService app/Services/InventarioService.php
Toda operación de stock ocurre dentro de DB::transaction(). Usa lockForUpdate() para prevenir race conditions cuando múltiples usuarios operan simultáneamente.
pub registrarEntrada(array $data): InventarioMovimiento
Parámetros requeridos en $data: medicamento_id, cantidad, motivo.
Flujo: lock → sumar stock → crear movimiento → registrar bitácora → notificar.
pub registrarSalida(array $data): InventarioMovimiento
Parámetros requeridos: medicamento_id, cantidad, motivo. Opcionales: consulta_id, paciente_id, recibido_por_nombre, recibido_por_cedula.
Flujo: lock → validar stock suficiente → restar stock → crear movimiento → verificar stock mínimo → notificar si bajo → bitácora.
Si el stock es insuficiente, lanza Exception("Stock insuficiente") que es capturada por el controlador y redirige al formulario con el mensaje de error.
// Ejemplo de uso desde un controlador use App\Services\InventarioService; public function store(Request $request, InventarioService $service) { try { $movimiento = $service->registrarSalida([ 'medicamento_id' => $request->medicamento_id, 'cantidad' => 2, 'motivo' => 'Dispensado por receta #42', 'recibido_por_nombre' => 'Juan Pérez', ]); } catch (Exception $e) { return back()->withErrors(['error' => $e->getMessage()]); } }

RecetaService

Coordina la dispensación de recetas con el módulo de inventario

service RecetaService app/Services/RecetaService.php
Encapsula la lógica de dispensación masiva. Llama a InventarioService::registrarSalida() una vez por cada RecetaItem dentro de la misma transacción.
pub dispensar(Receta $receta, array $datosFirma): void
Itera sobre $receta->items, registra una salida por cada ítem y marca la receta como dispensada. Todo dentro de una transacción DB.
